# Service layer — contract only, intentionally not implemented

## 状态

**未实现。** 服务层目前只有契约（`openapi.yaml`），没有服务代码。这是刻意的。另注：本目录里的 `worker.js` 是公共研究层的估算 API（见本目录 `README.md`），与服务层无关，勿混淆：

> 现在不建 SaaS。先把接缝划出来，让公共研究层可以独立演进，将来服务层长出来时不需要重写研究层。

判断"什么时候才该实现"的信号写在 [`../ARCHITECTURE.md`](../ARCHITECTURE.md) 第 6 节 —— 满足任意两条再动手（独立复现 ≥5、人工入库成为瓶颈、出现明确付费需求、有第二位长期维护者）。

## 为什么现在不做

| 理由 | 说明 |
|---|---|
| 会吸走研究层的产能 | 当前单维护者 + 1 条独立复现，最稀缺的是"让更多人跑起来"，不是平台 |
| 现有流程还能撑 | 浏览器校验 → 复制 Markdown → GitHub issue → 维护者入库，每月几十条完全够 |
| 契约比实现更难改 | 先把 `energy.json` schema 与校验规则定死（已完成），实现随时可以补 |
| 过早抽象会锁死错误设计 | 现在没有真实客户，权限模型大概率会猜错 |

## 唯一的耦合：JSON 契约

服务层**必须**接受并产出与公共研究层相同的 `energy.json`（`ecocompute-energy/1.x`）。
否则私有结果无法与已发布曲线比对 —— 那两层就白分了。

研究层已发布的校验规则（复现页浏览器校验器）应当被服务端**原样复用**：

- schema 版本与必需块
- GPU 名称 ↔ 声明架构一致性
- 采样率 ≥ 10 Hz（§4.1.2）
- 同场 FP16 基线（缺失则无法计算 ΔE%）
- 异常值**只标记不拒绝**
- 已知缺口：`thermal` 块 / Docker digest / commit hash 目前容器不输出 → 标为 warn，不伪造

## 部署选项（将来）

| 方案 | 适用 | 备注 |
|---|---|---|
| Cloud Run | 流量波动大、不想管机器 | 冷启动对"提交一个 JSON"足够友好 |
| 小 VPS | 成本敏感、流量可预测 | 单容器 + SQLite/Postgres 即可起步 |
| 国内节点 / 镜像 | 客户在国内、需要合规与低延迟 | 见下 |

### 国内镜像的优先级（按收益排序）

维护者已有实测数据：中国租卡环境下首次运行 57 分钟里，**torch/CUDA wheel 下载占了绝大部分**（模型下载仅约 5.5 分钟）。所以镜像顺序应当是：

1. **容器镜像同步到国内 registry** —— 收益最大，直接决定首次运行能否跑完
2. **PyPI / torch wheel 国内索引** —— `quickstart.sh` 已支持 `ECO_TORCH_INDEX`
3. **静态站 CDN / 国内镜像** —— 收益最小：站点是纯静态小文件，且研究层以"被引用"为主而非流量入口

**先做 1 和 2。** 静态站镜像可以最后做，甚至不做。

## 接入方式（将来只有一步）

静态站已经留好 `assets/data-source.js`。部署服务后，在页面里注入一行即可切换：

```html
<script>window.ECO_API_BASE = "https://api.quantenergy.tech/v1";</script>
<script src="/assets/data-source.js"></script>
```

未注入时 `EcoData.mode === "static"`，站点读静态 JSON，完全离线可用；
注入后 `mode === "api"`，同一套页面读 API，业务代码零改动。

## 治理红线

- 客户私有结果**默认不进入公共数据集**；同意公开时才走与任何人相同的校验流程并署名
- 服务层客户**不得**影响研究层结论；服务层数据若进入公共曲线，必须在 changelog 记录来源
- `MLPerf®` / `MLCommons` / `MLCube` 为 MLCommons 商标，服务层继承研究层的指示性引用约束
