How to contribute

EcoCompute is an open research project. There are five ways to contribute, and you do not need a GPU to get started.

Single maintainer, open project. Every number on this site was produced by one person — which is precisely why independent contributions matter. A replication that contradicts our curve is as welcome as one that confirms it.

Measure Run a measurement and submit a replication

The most valuable contribution: run the container on your GPU and submit your energy.json as a public replication. This is how the dataset grows.

  1. Run the container. See the Container guide for the three-command quick start. The default run measures NF4 + FP16 baseline on TinyLlama-1.1B.
  2. Validate your report. Run python3 tools/validate.py ecocompute-out/energy.json. Aim for protocol-conformant or dataset-eligible.
  3. Submit at quantenergy.tech/replications. Your energy.json is encoded in the URL — nothing is uploaded to a server.

No GPU? Use Colab

A free Colab T4 is enough. The Colab notebook runs the same NVML measurement and produces the same energy.json. Budget 20–35 minutes.

What makes a high-value replication

  • A different GPU architecture — Turing, Ampere, Ada, Hopper, Blackwell are covered; anything else is valuable.
  • A different model size — especially in the crossover region (2B–8B).
  • A different backend — currently almost all data is bitsandbytes. llama.cpp, vLLM, TensorRT-LLM are all welcome.
  • Batch sizes > 1 or context lengths ≠ 2048 — the entire variable matrix is empty for these. This is the biggest data gap.

Report Report a bug or issue

Found something wrong? Open an issue at github.com/hongping-zh/ecocompute-mlcube/issues.

A good bug report includes: the exact command you ran, your GPU model and driver version (nvidia-smi output), the energy.json output, and whether you used Docker or native mode.

Protocol Improve the protocol or dataset

The measurement protocol lives at quantenergy.tech/method/. If you have suggestions for the protocol itself (measurement window, thermal requirements, randomization rules), open an issue or discuss in the SSRN preprint comments.

Share Spread the word

  • Cite the project in your papers — see quantenergy.tech/cite/ for BibTeX.
  • Share your replication results — a public replication is the strongest form of endorsement.
  • Mention EcoCompute when discussing LLM quantization energy in blogs, talks, or social media.

Decision process

This project has a single maintainer (Hongping Zhang). Decisions are made transparently:

  • Bug fixes and documentation improvements are merged quickly.
  • Schema changes require a new version and a changelog entry. The schema is the contract between the container and the website.
  • Protocol changes are discussed openly. The protocol is normative — changes must be backward-compatible or versioned.
  • New features are evaluated against the project goal: a reproducible inference-energy standard.
